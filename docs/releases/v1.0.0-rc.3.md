## Highlights

1.0.0-rc.3 is a release candidate after [v1.0.0-rc.2](https://github.com/hilather/go-lab-netconf/blob/v1.0.0-rc.2/docs/releases/v1.0.0-rc.2.md). The Go toolchain pin is go1.26.9. The MCP protocol pin stays 2026-07-28.

- Live NETCONF session list and kill: `GET /v1/sessions`, `POST /v1/sessions/{id}:kill`, and MCP `netconf_sessions_list` / `netconf_session_kill` ([PR #12](https://github.com/hilather/go-lab-netconf/pull/12)). Admin kill does not close the SSH connection.

**Not in this tag:** NETCONF over TLS, RESTCONF TLS, RFC 8071 call-home (still v1.1). Integrator pin in mcp-integration-lab remains out of band.

## Changed

- Go toolchain pinned to go1.26.9 (`go.mod` toolchain, CI and release `GO_VERSION`, Dockerfile). Releases 1.26.0 through 1.26.8 lack current stdlib security fixes, most recently the Go 1.26.9 fixes (GO-2026-6603 to -6605, -6607 to -6613 and -6617 in `net/http`, `net/textproto`, `mime/multipart`, `crypto/tls` and `os`). `golang.org/x/net` is not a dependency of this module ([PR #11](https://github.com/hilather/go-lab-netconf/pull/11)).
- Web development dependency `source-map-js` updates from 1.2.1 to 1.2.2 (GHSA-68fv-2mgg-jv7q, high: event-loop denial of service through indexed source-map section offsets). Lockfile only; the built web assets are byte-identical ([PR #8](https://github.com/hilather/go-lab-netconf/pull/8)).
- Web development dependency `undici` updates from 8.10.0 to 8.10.2 (via jsdom; GHSA-rfgv-xxqx-mfg5, GHSA-w293-vg96-wgc3 and GHSA-vp8m-p9jh-q5pm high, plus eight moderate or low undici advisories). Lockfile only; the built web assets are byte-identical ([PR #10](https://github.com/hilather/go-lab-netconf/pull/10)).

## Fixed

- The release concurrency group is the same for a tag push and for a manual re-gate of that tag. A bare `workflow_dispatch` ref is prefixed with `refs/tags/`, so `vX.Y.Z` and `refs/tags/vX.Y.Z` share a group with the push of that tag. `cancel-in-progress` stays false ([PR #16](https://github.com/hilather/go-lab-netconf/pull/16)).
- A manual release re-gate checks the tag against `^v[0-9]+\.[0-9]+\.[0-9]+(-[0-9A-Za-z.-]+)?$` before checkout and checks out only `refs/tags/<tag>`. The workflow fails unless `HEAD` is that tag's peeled commit, passed as `-sha`. `release-gate` exits 75 only when that tag's CI run is missing or not completed, and the workflow retries only status 75. `publish-image` builds only the commit `tag-gate` approved ([PR #14](https://github.com/hilather/go-lab-netconf/pull/14)).
- A `workflow_dispatch` re-gate passes the tag and the checked-out commit to `release-gate -require-ci` as `-tag` and `-sha`, so a re-gate started from a branch judges that tag's CI run ([PR #13](https://github.com/hilather/go-lab-netconf/pull/13)).
- The tag release gate fails unless each required CI job name appears exactly once in that tag run and its conclusion is success. A later green copy no longer hides an earlier failure ([PR #15](https://github.com/hilather/go-lab-netconf/pull/15)).

## Security

- A present empty `allowClientCidrs` on `replaceAdmission` is deny-all. Omitted or null still becomes loopback ([PR #9](https://github.com/hilather/go-lab-netconf/pull/9)).
- `GET /v1/metrics` requires `netconf.read`. Health live and ready stay unauthenticated. Unauthenticated scrapers fail ([PR #9](https://github.com/hilather/go-lab-netconf/pull/9)).
- mcp-stdio keeps the startup bearer and drops that pin when the secret no longer authenticates after reset or apply ([PR #9](https://github.com/hilather/go-lab-netconf/pull/9)).
- A successful apply or reset updates NETCONF access, RESTCONF users and admission, and the SSH allow-list and credential bytes. Sessions whose user, access, profile or profile datastore changed are closed, and SSH connections of users whose password or authorized keys changed are closed. Listener addresses and host keys are unchanged ([PR #9](https://github.com/hilather/go-lab-netconf/pull/9), [PR #12](https://github.com/hilather/go-lab-netconf/pull/12)).
- The tag gate accepts only the completed push CI run for that tag and SHA. Only the newest tag-push run counts, and a newer in-progress tag run stays pending even when an older tag run is green ([PR #9](https://github.com/hilather/go-lab-netconf/pull/9)).
- Release checkout sets `persist-credentials: false` on both checkouts. The image build context excludes `.git`, `.github`, `docs`, and every `testdata` directory ([PR #15](https://github.com/hilather/go-lab-netconf/pull/15)).

## Residual

- Not a production device. Not netopeer2. Not a manager. No YANG 1.1 compiler.
- No NETCONF over TLS. No call-home. No YANG-Push. No NMDA operational datastore. No confirmed-commit. No XPath filter.
- RESTCONF HTTP only. JSON only. Cleartext RESTCONF is a laboratory limitation.
- Client `remoteAddr` is not exposed in session rows or notifications, because Docker `userland-proxy` SNAT is a NAT collision.
- Single replica. Memory store only. Reset and restart wipe the notification and audit rings.
- SSH `authorized_keys` options (`from=`, `command=`, `restrict`, and the rest) are parsed but not enforced at login. Only the key material is checked. A change to a key's options still counts as a credential change and closes that user's SSH connections.
- In-protocol NETCONF `<kill-session>` lets any read-write user kill another session. A read-only user gets access-denied. Admin `POST /v1/sessions/{id}:kill` is the scoped `netconf.admin` path.
- Integrator pin in mcp-integration-lab is **not** this tag (LAST, out of band).
- GHCR package may be private until a human marks it public. linux/arm64 not in this tag.
- Mira review is requested after the first UI landing.
